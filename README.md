### English

I combine a statistics background with a business analytics lens — I care about designing
analyses that hold up to scrutiny and translate into decisions, not just about getting a model to
run. Four end-to-end portfolio projects below, spanning SQL analytics, causal inference, and
supervised ML on sensor data — all built to the same standard: reproducible pipelines, correct
statistical methodology, and self-audited for real errors before publishing.

**Projects**

- **[A/B testing in a marketplace](https://github.com/luciaparvaz/ab-testing-marketplace-olist)** —
  full experimentation design on the Olist e-commerce dataset (CRISP-DM): power analysis, A/A
  calibration, guardrails with a two-gate decision rule, and a documented p-hacking failure mode
  found and fixed during a self-audit. Includes a business-facing executive summary and a
  from-scratch reproducible pipeline.

- **[Customer behavior analysis — Olist e-commerce](https://github.com/luciaparvaz/olist-customer-analysis)** —
  SQL (CTEs, window functions) + Python analytics on 96K orders: RFM customer segmentation,
  statistical drivers of negative reviews, and category-level retention analysis, with an
  interactive Plotly dashboard.

- **[Predictive maintenance — turbofan engine RUL](https://github.com/luciaparvaz/cmapss-rul-prediction)** —
  Master's thesis project (NASA C-MAPSS dataset): remaining-useful-life prediction with
  leakage-free feature engineering, model selection by cross-validation only, and corrected
  statistical tests (heteroscedasticity, autocorrelation) after a self-audit found and fixed a real
  bug in the evaluation metric.

- **[Predictive maintenance — hydraulic systems](https://github.com/luciaparvaz/hydraulic-predictive-maintenance)** —
  per-component failure classification (84–100% F1-macro) on industrial sensor data, with an
  anomaly-detection method shown to fail on this dataset and explained why, plus a
  group-held-out validation quantifying how much performance drops on genuinely new operating
  points.

**Stack:** Python · pandas · NumPy · SciPy · statsmodels · scikit-learn · SQL (SQLite) · Plotly ·

### Español

Combino una formación en estadística con una mirada de analítica de negocio — me importa que los
análisis aguanten el escrutinio y se traduzcan en decisiones, no solo que un modelo "funcione".
Cuatro proyectos de portfolio de principio a fin, desde analítica SQL e inferencia causal hasta ML
supervisado sobre datos de sensores — todos construidos con el mismo estándar: pipelines
reproducibles, metodología estadística correcta y auto-auditados en busca de errores reales antes
de publicarlos.

**Proyectos**

- **[A/B testing en un marketplace](https://github.com/luciaparvaz/ab-testing-marketplace-olist)** —
  diseño experimental completo sobre el dataset de e-commerce de Olist (CRISP-DM): power analysis,
  calibración A/A, guardrails con regla de dos puertas, y un fallo de p-hacking documentado que se
  encontró y corrigió en una auto-auditoría. Incluye resumen ejecutivo de negocio y un pipeline
  reproducible desde cero.

- **[Análisis de comportamiento de clientes — Olist e-commerce](https://github.com/luciaparvaz/olist-customer-analysis)** —
  SQL (CTEs, window functions) + analítica en Python sobre 96K pedidos: segmentación de clientes
  RFM, drivers estadísticos de reseñas negativas y análisis de retención por categoría, con un
  dashboard interactivo en Plotly.

- **[Mantenimiento predictivo — vida útil de motores turbofan](https://github.com/luciaparvaz/cmapss-rul-prediction)** —
  proyecto de fin de máster (dataset NASA C-MAPSS): predicción de vida útil restante con feature
  engineering sin fuga de datos, selección de modelo solo por validación cruzada, y contrastes
  estadísticos corregidos (heterocedasticidad, autocorrelación) tras una auto-auditoría que
  encontró y corrigió un bug real en la métrica de evaluación.

- **[Mantenimiento predictivo — sistemas hidráulicos](https://github.com/luciaparvaz/hydraulic-predictive-maintenance)** —
  clasificación de fallos por componente (84–100% F1-macro) sobre datos de sensores industriales,
  con un método de detección de anomalías cuyo fallo en este dataset se demuestra y explica, más
  una validación por grupos que cuantifica cuánto cae el rendimiento en puntos de operación
  genuinamente nuevos.

**Stack:** Python · pandas · NumPy · SciPy · statsmodels · scikit-learn · SQL (SQLite) · Plotly ·
